# CLAUDE.md — read this first, every session

This is **Samar's Game in Dubai** (https://gameindubai.com): free one-finger block games for kids aged 3–10 (and their parents), each set at a real Dubai tourist attraction, credited to Samar (8). Owner: Nihal. He is terse and expects decisive work, no scope creep, and **to be told about every trade-off**.

Claude Code loads this file automatically. In a chat session, start by reading this file, then `docs/COMMON_MISTAKES.md` (headings at least).

---

## 1. Non-negotiables
1. **Nothing ships untested.** Deploy only with `python3 scripts/deploy.py` (build → full suite → deploy → live checks) or via CI. Never drag-and-drop in the Cloudflare dashboard.
2. **Never remove, hide or shrink a feature the owner asked for to make something fit or pass.** Find the cause. If a trade-off is truly needed, say so explicitly in your reply. (See COMMON_MISTAKES #29.)
3. **Build games from `docs/CONCEPTS.md`**, not from memory or summaries. Rules: no animal is ever hit, chased or annoyed; every landmark ends each run looking better; one finger; ages 3–10 *and* adults.
4. **Every game must stay within the performance budgets** (section 4), enforced by `tests/test_perf.py`.
5. **One look.** Engine games get it automatically; standalone games must pass `tests/test_design.py` (see `docs/DESIGN_LANGUAGE.md` → Standalone games).
6. **If two games need the same code, it goes in `src/blockkit.js` → "Shared gameplay helpers".** Copy-paste between games fails `test_no_helper_is_copied_between_games`.
7. **Never edit `site/`.** It is generated by `build_site.py` from `src/`.

## 2. Session start (5 minutes, saves hours)
```bash
git pull
pip install -r requirements-dev.txt && python -m playwright install --with-deps chromium webkit
python3 build_site.py
python -m pytest -q -m "not live and not perf"   # fast suite (~5 min); must be green before you change anything
```
Then skim `docs/PERF_REPORT.md` (the current per-game baseline) so you can compare after your change.

## 4. Performance budgets (enforced in `tests/test_perf.py`; rationale in `docs/PERFORMANCE.md`)
| Budget | Limit | Current worst |
|---|---|---|
| Game-only download (uncompressed) | ≤ 150 KB | 62 KB (Pew Pew Space) |
| Shared download (three.js + kit + font) | ≤ 800 KB, cached once for all games | 665 KB |
| Draw calls per frame during play | ≤ 150 | ~92 (Fruit Rush) |
| GPU memory across 3 identical runs (15 s of game time each) | must not grow in **every** run (a leak's signature); ≤ 60 buffers total | Shine Crew +18 once (new crust type), Fruit Rush +6 once (new butterfly), others flat |
| Render scale on a 3× phone | ≤ 2× | 2× |
| Bot survives from wave 2 | ≥ 40 s (kid difficulty smoke test) | all pass |
| Requests to other servers | none (except Google Analytics) | none |

## 5. "If you touch X, watch Y" (each line is a real past bug)
| You change… | Watch out for | Guard |
|---|---|---|
| Home page CSS/JS | Desktop columns not fitting (fit ladder: big → row → tight → mini → stacked); stats or ▶ hidden; class-name collisions (`.stats` bug) | `test_home.py` (7 sizes × 2 engines), `test_css_classes_are_not_shared_between_pages` |
| Any new live game | Home column space (≈7+ games needs a redesign), card image must exist before build, sitemap/SW/worker allowlist | `test_build.py`, `test_home.py` |
| Game objects created at runtime | **Draw calls** (batch identical blocks with `InstancedMesh`/merged geometry); **GPU leaks** (share geometries; `dispose()` anything you create per object, incl. InstancedMesh) | `test_perf.py` |
| Materials | No lights in engine scenes: Lambert/Phong/Standard render **black**; use `VOXMAT` or `MeshBasicMaterial` | `test_engine_games_use_unlit_materials` |
| Fast-moving objects / collisions | **Tunnelling at low frame rates** (a window check misses when a frame is slow): use swept tests (did it cross the line this step?) | `test_perf.py` runs at 3× resolution = slow frames |
| Difficulty | Stack/wind/swing tuned for adults are brutal for 5-year-olds; measure with the bot | `test_perf.py` survival, `test_bot_scores_points` |
| Queues / spawners | Take due items out of the queue *before* processing (Dome 5 freeze) | regression tests in `test_games.py` |
| Random choices with properties | One roll decides type + properties (double-roll crash) | code review; see COMMON_MISTAKES #1 |
| Service worker / caching | Pages must stay network-first so fixes arrive on the next reload | `test_new_deploy_arrives_on_first_reload` |
| Pause / background / iOS | Auto-pause when hidden; AudioContext can be `closed`/`interrupted` on iOS; rAF can stall on resume | `test_every_game_pauses_when_the_app_is_hidden`, `test_frozen_animation_frames…` |
| Minified one-line code | Appending `// comment` mid-line comments out the rest | `test_all_javascript_parses` |
| CI workflow YAML | `key: value` inside a one-line `run:` breaks parsing and CI silently skips | `test_ci_workflow_is_valid_yaml` |
| Copying from another game | Put it in blockkit's shared helpers instead | `test_no_helper_is_copied_between_games` |

## 6. Definition of done
**New engine game:** concept from CONCEPTS.md → `src/<id>.world.js` + `.rules.js` using shared helpers → WORLDS `live:true` → `GAMES`/`GAME_BG`/`GAME_LINES` in build → real 480×360 card → phone + landscape screenshots reviewed → `docs/games/<id>.md` → README/registry/CONCEPTS table → `python3 tools/audit.py <id>` within budget → `scripts/deploy.py` green → push → CI green → tell the owner about any design trade-offs.

**Adopted standalone game:** as above, plus the bridge contract in `docs/GAME_ENGINE.md` → Standalone games, and `test_design.py` must pass (MAP, WORLD chip, place, pause, sound, pixel font, gold buttons, auto-pause).

**Any update:** fast suite before and after; `tools/audit.py` for affected games if you touched runtime code; update the docs you made stale; add a COMMON_MISTAKES entry + a test for any bug you fixed (and watch the test fail on the broken code first).
